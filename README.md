# مِعيار AI  منصة الامتثال الكهربائي

نموذج منتج احترافي مقدم إلى **الهاكاثون الهندسي SCE 2026** ضمن مسار التطوير الهندسي وتحدي التدقيق الآلي والامتثال للأكواد.

## المشكلة

مراجعة المخططات الكهربائية عملية يدوية متكررة، وتوزّع الملاحظات بين ملفات وجداول ورسائل يجعل القرار الهندسي بطيئًا وصعب التتبع.

## الحل

مِعيار AI يحول المخطط إلى نموذج بيانات هندسي، يشغّل حسابات وقواعد امتثال قابلة للتفسير، يربط كل ملاحظة بموقعها ودليلها، ثم يضع القرار النهائي بيد المهندس المرخص.

## ما يمكن تجربته الآن

- عارض مخطط أحادي تفاعلي مع تحديد مواقع المخالفات
- سجل ملاحظات مرتب حسب الخطورة والثقة والموقع
- تفاصيل الأدلة، القاعدة، والإجراء التصحيحي
- معالجة الملاحظات وتحديث درجة الامتثال مباشرة
- ورقة حسابات قابلة للتحرير لتيار التصميم وهبوط الجهد والتنسيق
- مكتبة قواعد بإصدارات ومعرّفات قابلة للتتبع
- مساحات للمشاريع والتقارير
- تقرير مراجعة قابل للطباعة
- تصميم عربي RTL متجاوب

## المعمارية المستهدفة

`PDF / CAD → OCR + Computer Vision → Electrical Graph → Deterministic Rule Engine → Explainable Findings → Engineer Approval`

يعتمد النموذج الحالي على بيانات تجريبية ومحرك حسابات يعمل داخل المتصفح لإثبات تجربة المنتج. النسخة الإنتاجية تربط خدمات استخراج PDF/CAD وقاعدة بيانات للإصدارات وسجل تدقيق غير قابل للتلاعب.

## إطار الامتثال

الإطار الأساسي المقترح هو **SBC 401-2024**، مع SBC 601/602 لكفاءة الطاقة ومتطلبات شركة الكهرباء السعودية وSASO عند انطباقها.

> لا يحتوي المستودع على نصوص محمية من الكود. معرّفات القواعد تجريبية، وتُربط البنود الرسمية فقط بعد الحصول على نسخة مرخصة والتحقق من القواعد بواسطة مهندسين مختصين.

## التشغيل محليًا

يتطلب المشروع Node.js 24 أو أحدث. الملفات الخام للمخططات لا تُرسل إلى خادم.

```sh
npm ci
npm run dev
```

افتح منفذ المعاينة 5000. يعمل الموقع كصفحات HTML/CSS/JavaScript معيارية بلا إطار واجهات أمامية أو اعتماد على خدمة خلفية. يلزم تقديمه عبر HTTP بدل فتح `index.html` مباشرة لأن الواجهة تستخدم وحدات ES.

## المعمارية

- `src/core/models.d.ts`: نماذج البيانات المهيكلة مع فحوصات JSDoc/TypeScript.
- `src/core/calculations.js`: حساب التيار ثلاثي الطور وهبوط الجهد وتجميع الأحمال؛ دوال حتمية ومدخلات صريحة.
- `src/core/rules.js` و`src/core/evaluator.js`: حزمة قواعد تجريبية ذات إصدارات وبيانات مصدر وتحقق ونتائج قابلة لإعادة الإنتاج.
- `src/core/demo-adapter.js`: محول عرض تجريبي شفاف؛ لا يقرأ الرسم المرفوع ولا يدعي استخدام نموذج ذكاء اصطناعي.
- `src/core/assessment.js`: مراحل التقييم، الاستخراج التجريبي، المراجعات، القرار البشري، وسجل التدقيق والتخزين المحلي.
- `src/core/report.js`: تقرير HTML ثنائي اللغة مستقل للطباعة أو التنزيل.
- `app.js`, `src/ui/i18n.js`, `styles.css`, `index.html`: واجهة عربية RTL وإنجليزية LTR مع تنقل hash يعمل على GitHub Pages.
- `tests/`: اختبارات الحسابات والقواعد والقرارات وإعادة الضبط والتقرير؛ اختبار المتصفح يُشغّل عندما يتوفر Chromium.

## الاختبارات والبناء

## مسارات المنتج

- إنشاء تقييم مع بيانات المشروع، المراجع، رقم الرخصة، الإصدار وقياسات وقت اختيارية لإثبات الأثر لاحقًا.
- استقبال PDF أو DWG أو DXF بحد 20 MB؛ المعاينة المحلية لملف PDF فقط. لا تُحفظ بايتات الملف الخام.
- نموذج SLD وجدول معدات مستنتجان من سجل العينة. كل تحليل يستخدم البيانات الثابتة نفسها بدل الادعاء بأنها قُرئت من المخطط.
- حساب تيار ثلاثي الطور، الطلب، هبوط الجهد، سعة كابل مدخلة، اكتمال التأريض والتصنيفات، تسميات المعدات، توازن الأطوار ومعلومات الرسم.
- النتائج تعرض سلسلة دليل مفترضة في الرسم التجريبي → القيمة → الحساب → القاعدة → الإجراء → قرار المهندس.
- قبول أو رفض أو تعليم المعالجة مع تعليق وهوية المراجع ووقت القرار. الرفض خلاف هندسي مسجل ولا يعني النجاح التلقائي.
- توقيع إتمام المراجعة يشترط اتخاذ قرار بكل ملاحظة، لكنه إقرار محلي ذاتي وليس تحقق هوية أو توقيعًا مشفرًا أو اعتمادًا للتصميم.
- تاريخ محلي للتقييمات المكتملة، بحث وتصنيف لقواعد الحزم، تقارير قابلة للطباعة، ووضع عرض معزول لا يغير السجل الحقيقي.
- صفحة عن المنتج وخطة تجربة تشغيلية لمدة 90 يومًا بأهداف معلنة كأهداف مستقبلية لا نتائج مزعومة.

## حدود مهمة قبل تجربة ميدانية أو إنتاج

المنتج هنا نموذج أولي بلا واجهة ذكاء اصطناعي حية أو محلل PDF/CAD أو خلفية مشتركة. جميع الملفات تربط بنموذج معدات تجريبي ثابت. تقييم ثقة العناصر لا يُشتق من مستند المستخدم. السجلات والمتصفح محليان وقابلان للتعديل ولا يمثلان سجل تدقيق غير قابل للتلاعب. تتطلب بيانات العملاء الحقيقية وضوابط وصول ونُسخًا احتياطية وخدمة مركزية معتمدة.

المراجع تشير إلى SBC 401 ومتطلبات شركة الكهرباء السعودية ومبادئ IEC 60364 وإطار SASO ومواصفات المشروع بوصفها **فئات مصادر محتملة** فقط. المعرّفات والحسابات وحدود المشروع بيانات توضيحية، والبنود غير مرقمة بمرجع رسمي مصادق عليه. لا يتضمن المستودع نصوصًا مرخصة أو قواعد تم اعتمادها من جهة رسمية؛ تعرض القواعد عبارة: “Demo rule – pending validation against the licensed authoritative source.” يجب مراجعة جداول السعة والعوامل الحرارية وطريقة التمديد والانتقائية والقصر والتأريض وحدود هبوط الجهد مع المهندس والمصادر المرخصة. لا يستخدم هذا التطبيق منفردًا لإصدار أو اعتماد تصميم تنفيذي.

## النشر إلى GitHub Pages

يحتوي المستودع على GitHub Actions workflow لاختبار البناء الثابت `dist/` ونشره. تُفعّل صلاحيات Pages في إعدادات مستودع GitHub، ثم يُدفع التغيير إلى `main` أو يُشغّل الإجراء يدويًا. يعتمد عنوان GitHub Pages الفعلي على إعدادات الحساب والمستودع. المسارات داخل الموقع نسبية وروابط الصفحات تستخدم `#...` لتفادي إعداد خادم SPA.
